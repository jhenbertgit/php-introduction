What is Programming? 🤔

Programming is simply giving instructions to a computer in a language it understands. Think of it like writing a recipe for a very obedient but very literal-minded chef. You wouldn't tell a chef "make dinner" — you'd give them step-by-step instructions: "Chop the onions, heat the pan to medium, cook for 10 minutes." Programming works the exact same way.

In this analogy: your ingredients are data (numbers, text, images), your recipe steps are instructions (add this, multiply that, display this), and the chef is the computer — incredibly fast, but completely unable to think for itself. It will follow your instructions precisely, even if they're wrong.

That last point is crucial: computers are fast but stupid. They do EXACTLY what you tell them — nothing more, nothing less. If you say "add 2 and 2," you get 4. If you accidentally say "add 2 and 3," you get 5. The computer won't say "Hey, I think you meant 2." It just executes. This is why being precise matters so much in programming.

Humans normally speak English, Spanish, Mandarin, etc. But computers speak in electrical signals — basically binary: 0s and 1s. Very few people write instructions directly in binary (and those who do are superheroes). Instead, we use programming languages — like PHP, Python, JavaScript, Java, and hundreds more — which are designed to be readable by humans, and then get translated into machine code behind the scenes.

Each programming language has its own strengths. Python is great for data science, JavaScript runs in web browsers, Java powers Android apps, and PHP is one of the best languages for building websites. We'll be learning PHP in this guide — and the good news is, once you understand programming concepts in one language, learning others becomes much easier. 

<?php
// Recipe: Make a greeting
// Step 1: Get the person's name
$name = "Alice";

// Step 2: Create the greeting
$greeting = "Hello, " . $name . "!";

// Step 3: Show the result
echo $greeting;
Hello, Alice!

Change "Alice" to your own name. What happens? Try using a friend's name, or even a silly word. The computer will happily greet anyone or anything — it doesn't judge!

What is PHP? 🐘

PHP stands for "PHP: Hypertext Preprocessor." Yes, that's a recursive acronym — the acronym contains itself. Confusing? Absolutely. Do you need to remember it? Nope. Everyone just calls it PHP.

PHP is a server-side language, which means it runs on a server — a powerful computer somewhere in a data center — not in your web browser. Here's the flow: your browser sends a request to the server, the server runs the PHP code, PHP generates HTML, and then the browser displays that HTML as a beautiful web page. You never actually see the PHP code itself — it all happens behind the scenes.

PHP is free and open-source, which means anyone can use it and anyone can contribute to improving it. It powers roughly 77% of websites that use server-side code. That list includes WordPress (which runs 43% of ALL websites), Wikipedia, Facebook (in its early days), and millions of others. PHP is everywhere.

The current version is PHP 8.4 (released November 2024), and it's faster, safer, and more feature-packed than ever. PHP files always end in .php and always start with <?php — that's the tag that tells the server "Hey, the following code is PHP, please run it."

What can PHP do? A better question might be: what can't it do? PHP can build web pages, create APIs (ways for apps to talk to each other), run command-line scripts, connect to databases, process forms, handle file uploads, send emails, generate PDFs, manipulate images, and much more. It's a genuine workhorse. 

<?php
// This tells the browser we're sending HTML
echo "<!DOCTYPE html>";
echo "<html><head><title>My PHP Page</title></head>";
echo "<body>";

// PHP calculates something
$year = 2026;
$birthday = 2000;
$age = $year - $birthday;

// And sends the result to the browser
echo "<h1>Happy Birthday!</h1>";
echo "<p>You are $age years old!</p>";

echo "</body></html>";
HTML page with "You are 26 years old!"

How the Web Works 🌍

When you type a URL into your browser and press Enter, something magical happens — except it's not magic, it's a very organized conversation between your computer and another computer far away. Let's break it down.

Here's the full journey in a simple diagram:

  ┌──────────┐         ┌──────────┐         ┌──────────┐
  │          │         │          │         │          │
  │  YOUR    │ ──req──▶│ INTERNET │ ──req──▶│  SERVER  │
  │  BROWSER │         │          │         │          │
  │          │◀──res── │          │◀──res── │  ┌────┐  │
  └──────────┘         └──────────┘         │  │ PHP│  │
                                            │  └────┘  │
                                            │  ┌────┐  │
                                            │  │ DB │  │
                                            │  └────┘  │
                                            └──────────┘

Step by step, here's what happens:

  • 1. You type https://example.com in your browser and press Enter
  • 2. Your browser sends a REQUEST: "Hey server, send me the homepage!"
  • 3. The server receives the request and finds the right PHP file
  • 4. PHP executes the code — it might calculate things, read from a database, check if you're logged in
  • 5. PHP sends back HTML as the response
  • 6. Your browser renders that HTML into the visual page you see

This all happens in milliseconds. Seriously — the entire back-and-forth often takes less than 100 milliseconds. Faster than you can blink.

Two important terms to know: Client and Server. Your web browser is the client — it asks for things. The remote computer is the server — it serves things. PHP runs on the server, which is why it's called a "server-side" language.

JavaScript, on the other hand, runs in your browser — that's "client-side." PHP and JavaScript are teammates: PHP builds the initial page on the server, then JavaScript adds interactivity in the browser (animations, popups, form validation). They work together to create the web experiences you use every day.

You'll see every image, script, and data request your browser makes. Hit refresh and watch them flood in again. That's the conversation happening right in front of your eyes.

Setting Up Your Environment 🔧

Before you can write PHP, you need three things: PHP itself (the language interpreter), a web server (like Apache or Nginx — this handles browser requests), and a code editor (where you write your code — VS Code is the most popular free option).

There are several ways to get all of this running. Here are your options, from easiest to hardest:

  • OPTION 1 — Docker (Recommended): You already have this set up! Just run docker compose up, place your files in the public/ folder, and visit http://localhost in your browser. Everything works instantly.
  • OPTION 2 — All-in-one packages: Tools like XAMPP, MAMP, or Laragon install Apache + PHP + MySQL all at once. Great for beginners who want a one-click setup.
  • OPTION 3 — Online sandboxes: Websites like onlinephp.io and 3v4l.org let you write and run PHP code directly in your browser. No installation needed — perfect for quick experiments.
  • OPTION 4 — Manual install: Download PHP from php.net/downloads and configure Apache separately. This is the hardest option and not recommended for beginners.

To verify PHP is working, open your terminal and run php -v. You should see something like PHP 8.4.x. If you see that, you're golden!

In this project, your public/ folder is the web root — that's where all your PHP files live. Any file you put there can be accessed in the browser. The workflow is simple: edit a file, save it, refresh your browser. That's it. No compiling, no building, no waiting.

Your First PHP File 📄

Let's break down the most important PHP line you'll ever write, character by character: 

<?php echo "Hello World"; ?>

Let's dissect every single piece:

  • <?php — The opening tag. This tells the server "Everything after this is PHP code, please run it." Every PHP file starts with this.
  • echo — A PHP command that means "output this." Whatever comes after echo gets sent to the browser.
  • "Hello World" — A string (text) wrapped in quotes. The quotes tell PHP "this is text, not code."
  • ; — The semicolon. This is like a period at the end of a sentence. It tells PHP "this instruction is done, move to the next one." Forget it, and PHP gets confused.
  • ?> — The closing tag. It means "PHP code ends here." Fun fact: this is actually optional at the end of a file, and most PHP developers skip it to avoid accidental whitespace issues.

Now let's make it more interesting by using variables — those are like labeled boxes where you can store data: 

<?php
// Storing data in variables (like labeled boxes)
$name = "World";

// Using a variable in output
echo "Hello, " . $name . "!";
//                ^ the dot connects strings together
Hello, World!

Three key things to notice here:

  • Variables always start with a $ dollar sign — that's how PHP knows it's a variable and not a regular word.
  • The = sign doesn't mean "equals" like in math class. In programming, it means "store this value in this variable." The math "equals" uses == (two equals signs) in PHP.
  • The . (dot) connects two strings together — this is called concatenation. Think of it as gluing text together. "Hello, " . $name . "!" glues three pieces into one: "Hello, World!"
🧪 Try It:

Create public/hello.php, write the code above, and visit http://localhost/hello.php. Then change "World" to your own name, save, and refresh. Welcome to programming — you just wrote dynamic output!

Reading Error Messages ⚠️

Here's a secret that experienced programmers know: errors are not scary. They're not a judgment of your skills, they're not something to be embarrassed about, and they certainly don't mean you're bad at this. Errors are simply the computer telling you WHAT went wrong and WHERE. That's actually incredibly helpful!

PHP has several types of errors, from mild to catastrophic. Here they are from least to most severe:

  • Notice — A minor issue. Your code still runs, but PHP is nudging you. Example: using a variable that doesn't exist yet. Annoying but harmless.
  • Warning — A real problem, but PHP tries to keep going. Example: trying to open a file that doesn't exist. You should fix these, but they won't crash your whole page.
  • Parse Error — A syntax mistake. PHP can't even understand your code, so it won't run at all. This is the most common error for beginners, and it's usually a missing semicolon or quote.
  • Fatal Error — Something broke so badly that PHP gives up entirely. Your code stops immediately. These are serious and usually mean a function doesn't exist or a required file is missing.

Every error message has the same anatomy. It tells you four things: the type of error, a message describing what happened, the file path where it happened, and the line number. That's everything you need to find and fix the problem.

The most common beginner mistake by far? Forgetting the semicolon ;. Let's see what that looks like: 

<?php
// ❌ BROKEN: Missing semicolon!
$name = "Alice"     // <-- forgot the ; here
echo $name;
Parse error: syntax error, unexpected token "echo", expecting ";"
in /public/docs/hello.php on line 4

Here's how to read that error message like a pro:

  • "Parse error" = syntax problem. PHP couldn't understand the code structure.
  • "unexpected token echo" = PHP was surprised to see echo here, because the previous line wasn't properly finished.
  • "expecting ;" = PHP is literally telling you what it wants: a semicolon!
  • "on line 4" = the line where PHP noticed the problem. Pro tip: the actual mistake is usually on the line before the reported line.

Here's the fixed version:

<?php
// ✅ FIXED: Added the semicolon
$name = "Alice";    // <-- semicolon added!
echo $name;
Alice

Four tips for debugging that will save you hours of frustration:

  • 1. Read the error message carefully. It really does tell you what's wrong. Don't panic-scan it — read each word.
  • 2. Check the line number. Look at that line AND the line before it. Most parse errors are caused by something missing on the previous line.
  • 3. Look for the common suspects. Missing ;, missing ", mismatched ( and ), or a typo in a function name.
  • 4. Search the error online. Copy and paste the error message into Google or your favorite search engine. Guarantee someone has had this exact same error before you.
🧪 Try It:

Go ahead — remove a semicolon from one of your PHP files on purpose. See the error? Now read it carefully, fix it, and confirm it works again. Getting comfortable with errors now will save you so much frustration later. Every programmer, even the ones with 20 years of experience, still makes these mistakes!

Variables

If PHP code is a recipe, then variables are the ingredients. A variable is a labeled box that stores a piece of data — a number, a word, a whole list of things, or even a true/false value. You give the box a name, put something inside, and then use the name whenever you need that value later.

In PHP, every variable starts with a dollar sign $. That's how PHP knows "this is a variable, not a regular word." The dollar sign is part of the name — you always write it.

Naming rules: After the $, the next character must be a letter or underscore. You can use letters, numbers, and underscores after that. No spaces, no special characters like @ or !, and the name is case-sensitive — $Name and $name are two different variables.

Assignment uses a single = sign (meaning "store this value"). Reading the variable is simply using its name with the $. 

<?php
// Creating variables
$name = "Alice";
$age = 30;
$isStudent = false;
$gpa = 3.85;

// Reading variables — just use the name
echo "Name: $name, Age: $age\n";
echo "Student: " . ($isStudent ? "Yes" : "No") . "\n";
echo "GPA: $gpa\n";
Name: Alice, Age: 30
Student: No
GPA: 3.85

Notice something powerful: string interpolation. Inside double-quoted strings, PHP automatically replaces $name with its value. You don't need concatenation. However, this only works with double quotes "...", not single quotes '...' — single quotes treat everything literally.

You can also modify a variable after creating it: 

<?php
$score = 50;
echo "Initial score: $score\n";  // 50

// Modify the variable
$score = $score + 10;
echo "After bonus: $score\n";    // 60

// Shorthand assignment operators
$score += 5;    // same as $score = $score + 5
echo "After add: $score\n";    // 65

$score *= 2;    // same as $score = $score * 2
echo "After double: $score\n";  // 130
Initial score: 50
After bonus: 60
After add: 65
After double: 130

PHP also supports variable variables — a variable whose name is stored in another variable. This is a niche feature, but it exists: 

<?php
// Variable variables (bonus — use sparingly!)
$color = "red";
$$color = "apple";    // same as $red = "apple"

echo $red;            // apple
echo $$color;         // apple (same thing)

Data Types

Every value in PHP has a type — it's either text, a number, a true/false flag, nothing at all, a collection of values, or something more complex. PHP has 8 scalar and compound types:

  • String — text like "hello" or "Alice"
  • Integer — whole numbers like 42 or -7
  • Float — decimal numbers like 9.99 or 3.14
  • Boolean — true or false
  • Null — explicitly "no value" — not zero, not empty string, just null
  • Array — an ordered collection of values
  • Object — an instance of a class (more on this later)
  • Resource — a special reference to an external resource (like a database connection or file handle)

You can check a variable's type anytime with gettype(). This is incredibly useful when debugging. 

<?php
$name = "Alice";            // string
$age = 30;                  // int
$price = 9.99;              // float
$isActive = true;            // bool
$nothing = null;             // null
$hobbies = ["coding", "reading"]; // array

echo gettype($name);         // string
echo "\n";
echo gettype($age);          // integer
echo "\n";
echo gettype($price);        // double
echo "\n";
echo gettype($isActive);     // boolean
echo "\n";
echo gettype($nothing);      // NULL
echo "\n";
echo gettype($hobbies);      // array

Pay attention: gettype() returns "double" for floats — that's a quirk of PHP's history. In practice, you'll also see developers use is_string(), is_int(), is_float(), is_bool(), is_null(), and is_array() for type checking, since these return true/false and are more readable in if statements.

Watch out for type juggling! PHP sometimes automatically converts types for you. This can cause surprising behavior: 

<?php
// Type juggling — PHP converts types automatically
$sum = 5 + "3 apples";      // PHP converts "3 apples" to 3
echo "Sum: $sum\n";          // Sum: 8

$check = "0" == false;
var_dump($check);            // bool(true) — surprising!
echo "\n";

// That's why we have === (strict comparison)
$strict = "0" === false;
var_dump($strict);           // bool(false) — correct!

bool(false)

This is why === (strict comparison) is almost always preferred over == (loose comparison). With ===, PHP checks both the value AND the type. With ==, PHP converts types behind the scenes and you can get unexpected results.

Operators

Operators are the symbols that perform actions on values. You've already met a few: = for assignment, . for string concatenation, and + for addition. PHP has a rich set of operators organized into categories.

Arithmetic operators do math: + add, - subtract, * multiply, / divide, % modulo (remainder), ** exponentiation, and intdiv() for integer division.

Assignment operators combine assignment with an operation: =, +=, -=, *=, /=, .= (concatenate and assign).

Comparison operators compare two values and return true or false: == (loose equal), === (strict equal), !=/!== (not equal), <, >, <=, >=, and <=> (spaceship).

Logical operators combine conditions: && (and), || (or), ! (not). PHP also has English words and, or, xor — but beware, they have lower precedence than && and ||, which can cause bugs. 

<?php
// Arithmetic
echo 10 + 3 . "\n";       // 13
echo 10 % 3 . "\n";       // 1 (remainder)
echo 2 ** 10 . "\n";      // 1024 (2 to the power of 10)
echo intdiv(10, 3) . "\n"; // 3 (integer division)

// String concatenation
$first = "Hello";
$second = "World";
echo $first . " " . $second . "!\n"; // Hello World!

// Concatenation assignment
$msg = "Hello";
$msg .= " there";    // same as $msg = $msg . " there"
echo $msg . "\n";    // Hello there

<?php
// Null coalescing — use a default when value is missing/null

Increment and decrement operators are shorthand for adding or subtracting 1: 

<?php
$count = 5;

Strings

Strings are sequences of characters — basically, text. PHP is extremely flexible with strings and gives you dozens of built-in functions for manipulating them. Let's start with the two ways to define strings.

Single quotes '...' are literal. Everything inside is treated exactly as written. The only escapes are \\ (literal backslash) and \' (literal single quote). No variable interpolation, no special characters like \n.

Double quotes "..." are parsed. PHP processes escape sequences like \n (newline), \t (tab), and interpolates variables directly into the string. 

<?php
$name = "Alice";

// Single quotes — literal, no interpolation
echo 'Hello, $name!\n';     // Hello, $name!\n (literally!)
echo "\n";

// Double quotes — parsed, variables replaced
echo "Hello, $name!\n";     // Hello, Alice!
echo "Today is " . date("l") . "\n";

// Curly brace syntax for complex variable names
$fruit = ["apple" => "red", "banana" => "yellow"];
echo "The {$fruit['apple']} is tasty\n";  // The red is tasty
Hello, $name!\n
Hello, Alice!

The red is tasty

Functions

A function is a reusable block of code with a name. Instead of writing the same logic over and over, you wrap it in a function, give it a name, and call it whenever you need it. Functions are the building blocks of well-organized PHP code.

The basic syntax is function name(params) { body }. You pass data in through parameters and get data back through a return value.

  • Named arguments (PHP 8.0+) let you pass arguments by name instead of position. This makes calls more readable and lets you skip optional parameters.

Include & Require

As your PHP projects grow, you'll want to split code across multiple files — a header here, a footer there, a database connection somewhere else. PHP provides four statements for loading external files:

  • include — loads a file. If the file is missing, PHP issues a warning but keeps running.
  • require — loads a file. If the file is missing, PHP throws a fatal error and stops immediately.
  • include_once — same as include, but PHP remembers what it already loaded and won't load the same file twice.
  • require_once — same as require, with the same "only once" protection.

Use require_once for critical files like database connections and function libraries (you need them, and loading them twice causes "already defined" errors). Use include for optional content like template partials where a missing file shouldn't crash your page.

The __DIR__ magic constant gives you the directory of the current file — always use it for paths to avoid confusion about which directory PHP is looking in.

Error Handling

Things go wrong in code — files don't exist, databases crash, users enter invalid data, network connections fail. Exception handling is how you deal with these problems gracefully instead of letting your entire application crash with an ugly error message.

The mechanism is try / catch / finally. You wrap risky code in a try block. If something goes wrong, you throw an exception, and the catch block handles it. The finally block always runs — whether an exception was thrown or not — making it perfect for cleanup code like closing database connections. 

<?php
function divide(float $a, float $b): float {
    if ($b === 0.0) {
        throw new InvalidArgumentException("Cannot divide by zero");
    }
    return $a / $b;
}

try {
    echo divide(10, 3) . "\n";     // 3.333...
    echo divide(10, 0) . "\n";     // throws exception!
} catch (InvalidArgumentException $e) {
    echo "Error: " . $e->getMessage() . "\n";
} finally {
    echo "Calculation attempted.\n";
}
3.3333333333333
Error: Cannot divide by zero
Calculation attempted.

Notice that "Error: Cannot divide by zero" is printed, but "Calculation attempted." also prints. That's the power of finally — it runs no matter what. Even if the catch block had its own error, finally would still execute.

The Exception object has several useful methods:

  • getMessage() — the error message you passed in
  • getCode() — an optional error code
  • getFile() — the file where the exception was thrown
  • getLine() — the line number where it was thrown
  • getTrace() — the full stack trace (call chain)

You can have multiple catch blocks to handle different types of exceptions: 

<?php
function readFile(string $path): string {
    if (!file_exists($path)) {
        throw new RuntimeException("File not found: $path");
    }
    if (!is_readable($path)) {
        throw new RuntimeException("File not readable: $path");
    }
    return file_get_contents($path);
}

try {
    echo readFile("/nonexistent/file.txt");
} catch (RuntimeException $e) {
    echo "Runtime Error: " . $e->getMessage() . "\n";
    echo "File: " . $e->getFile() . " on line " . $e->getLine() . "\n";
} catch (Exception $e) {
    // Catch any other type of exception
    echo "Unexpected error: " . $e->getMessage() . "\n";
}

echo "Program continues...\n";

You can create custom exceptions by extending the Exception class. This helps you categorize errors in your application: 

<?php
// Custom exception
class ValidationException extends Exception {
    private array $errors;

    public function __construct(array $errors) {
        $this->errors = $errors;
        parent::__construct("Validation failed");
    }

    public function getErrors(): array {
        return $this->errors;
    }
}

function validateEmail(string $email): void {
    $errors = [];
    if (empty($email)) {
        $errors[] = "Email is required";
    }
    if (!str_contains($email, "@")) {
        $errors[] = "Email must contain @";
    }
    if (!str_contains($email, ".")) {
        $errors[] = "Email must contain a domain";
    }
    if (count($errors) > 0) {
        throw new ValidationException($errors);
    }
}

// Usage
try {
    validateEmail("invalid-email");
} catch (ValidationException $e) {
    echo "Validation failed!\n";
    foreach ($e->getErrors() as $error) {
        echo "  - $error\n";
    }
}

Best practices:

  • Be specific — catch the most specific exception type first, then broader types. Always catch RuntimeException before Exception.
  • Don't swallow exceptions — an empty catch block silently hides errors. At minimum, log the error.
  • Use finally for cleanup — closing files, database connections, and releasing resources.
  • Throw early, catch late — throw exceptions as soon as something goes wrong, but catch them at a high level where you can respond appropriately.

OOP Basics 🏗️

Object-Oriented Programming (OOP) is a paradigm that organizes code around objects — self-contained bundles of data and behavior. Think of a class as a blueprint and an object as the thing built from that blueprint. A Car class is the engineering drawing; $myCar = new Car("Toyota", "red") is an actual car sitting in the garage.

Inside a class you define properties (variables that belong to the object) and methods (functions that belong to the object). The constructor __construct() is a special method that runs automatically when you create an object with new — use it to set up initial state. Inside methods, $this refers to the current object instance, letting you access its own properties and methods.

PHP 8.0+ supports constructor property promotion — you can declare and assign properties directly in the constructor signature, cutting boilerplate dramatically. Access modifiers (public, protected, private) control who can see and modify an object's data — a concept called encapsulation. 

<?php
class User {
    public string $name;
    public string $email;
    private int $age;

    public function __construct(string $name, string $email, int $age) {
        $this->name = $name;
        $this->email = $email;
        $this->age = $age;
    }

    public function getGreeting(): string {
        return "Hi, I'm {$this->name}!";
    }

    public function isAdult(): bool {
        return $this->age >= 18;
    }
}

$user = new User("Alice", "alice@example.com", 25);
echo $user->getGreeting() . "\n";
echo $user->isAdult() ? 'Adult' : 'Minor';
Hi, I'm Alice!
Adult

PHP 8.0 introduced constructor property promotion, which collapses property declaration and constructor assignment into a single line. Compare the verbose version above with this streamlined approach: 

<?php

    // Properties declared and assigned in one step
    public function __construct(
        public string $title,
        public string $author,
        public int $pages,

    }

    public function isLong(): bool {
        return $this->pages > 300;
    }

<?php
class Counter {

Access Modifiers 🔒

Access modifiers are the gatekeepers of your class. They decide who can see and touch what inside an object. PHP has three levels:

  • public — accessible from anywhere. Any code that has a reference to the object can read or write public properties and call public methods.
  • protected — accessible within the class itself and any child classes that extend it. Outside code cannot touch it.
  • private — accessible only within the class that defines it. Not even child classes can see private members.

This is called encapsulation — hiding internal implementation details and exposing a controlled public interface. Why does this matter? Because when you control how data is accessed, you can validate input, prevent invalid state, and change internals without breaking outside code.

The typical pattern: make properties private and provide public getter and setter methods. This lets you add validation logic at the boundary. 

<?php
class BankAccount {
    private float $balance;

    public function __construct(float $initialBalance = 0.0) {
        if ($initialBalance < 0) {
            throw new InvalidArgumentException("Initial balance cannot be negative");
        }
        $this->balance = $initialBalance;
    }

    public function deposit(float $amount): void {
        if ($amount <= 0) {
            throw new InvalidArgumentException("Deposit must be positive");
        }
        $this->balance += $amount;
    }

    public function withdraw(float $amount): void {
        if ($amount <= 0) {
            throw new InvalidArgumentException("Withdrawal must be positive");
        }
        if ($amount > $this->balance) {
            throw new RuntimeException("Insufficient funds: need $amount, have {$this->balance}");
        }
        $this->balance -= $amount;
    }

    public function getBalance(): float {
        return $this->balance;
    }
}

$account = new BankAccount(100.00);
$account->deposit(50.00);
$account->withdraw(30.00);
echo "Balance: $" . number_format($account->getBalance(), 2);
Balance: $120.00

Notice how $balance is private. Nobody can set it to a negative number directly — they must go through deposit() and withdraw(), which enforce business rules. This is the core value of encapsulation: protecting invariants.

Inheritance & Polymorphism 🧬

Inheritance lets a child class extends a parent class, automatically inheriting all its public and protected properties and methods. The child can then add new functionality or override (redefine) parent methods to change behavior. Use parent:: to call the parent's version of an overridden method.

Polymorphism means "many forms." When multiple classes share a common parent or interface, you can treat them all as the same type and call the same method — but each class responds differently. This is incredibly powerful: write code once that works with a concept, and it automatically works with every concrete implementation.

The final keyword prevents inheritance or method overriding: final class stops the class from being extended, and final public function stops a specific method from being overridden. Use this when you need to guarantee behavior won't change in subclasses. 

<?php

        return "{$this->name} says: {$this->speak()}";

Interfaces & Abstract Classes 📜

Interfaces define a contract — a list of method signatures that any implementing class must fulfill. They contain no implementation themselves, only method names, parameters, and return types. A class uses implements to promise it will implement every method the interface declares.

Abstract classes sit between interfaces and concrete classes. They can provide both abstract method signatures (which children must implement) and concrete method implementations (which children inherit directly). You cannot instantiate an abstract class with new — it exists to be extended.

The key difference: a class can implements multiple interfaces but can only extends one class. Use interfaces when you want to define what something can do (capabilities). Use abstract classes when you want to share how something partially works (common code + contract). 

<?php
interface Loggable {
    public function toLog(): string;
}

interface JsonSerializable {
    public function toJson(): string;
}

    public function getId(): int;

    protected \DateTime $createdAt;

Namespaces 📁

As your project grows, you'll inevitably run into name collisions: two different libraries both define a User class, or you have your own Logger and a logging package also has one. Namespaces solve this by putting classes into named groups, just like folders organize files on your computer.

A namespace is declared with namespace App\Models; at the very top of a file (before any other code except declare()). To use a class from another namespace, you use it: use App\Models\User;. You can also alias imports to avoid conflicts: use App\Models\User as UserModel;.

Type Declarations 📊

PHP is dynamically typed by default, meaning variables can change type at runtime. Type declarations let you enforce specific types on function parameters and return values, catching bugs early. A type mismatch that would have silently coerced in old PHP now throws a TypeError.

declare(strict_types=1) at the top of a file enables strict mode — PHP will not auto-coerce types. Without it, PHP tries to convert values silently ("42" becomes 42). With it, passing "42" where int is expected throws a TypeError. Always use strict mode in modern PHP.

PHP's type system is rich: union types (int|string) accept multiple types, nullable types (?string, equivalent to string|null) accept a type or null, and intersection types (Iterator&Countable) require a value to implement multiple interfaces simultaneously. 

<?php
declare(strict_types=1);

// Union types (PHP 8.0+): accept multiple types
function processInput(int|string $input): string {
    return match (true) {
        is_int($input)   => "Number: $input",
        is_string($input) => "Text: $input",
        default           => "Unknown",
    };
}

echo processInput(42) . "\n";
echo processInput("hello") . "\n";
// echo processInput(3.14);  // TypeError! float is not int|string
Number: 42
Text: hello

Enums 🆕 PHP 8.1

Enumerations (enums) are a fixed set of named values — a type that can only be one of a predefined list. Before PHP 8.1, developers used class constants or string literals, which were error-prone: misspell "active" as "actve" and your code silently breaks.

PHP 8.1 introduced two kinds of enums:

  • Pure enums — just named cases with no underlying value: enum Status { case Active; case Inactive; }
  • Backed enums — each case has a string or integer value: enum Status: string { case Active = 'active'; }

Enums can have methods, implement interfaces, use traits, and work seamlessly with match() expressions. The ::cases() method returns all enum cases, and ::from() / ::tryFrom() creates an enum from a backing value (throwing or returning null on failure respectively). 

<?php
enum HttpMethod: string {
    case Get    = 'GET';
    case Post   = 'POST';
    case Put    = 'PUT';
    case Delete = 'DELETE';

    public function isSafe(): bool {
        return $this === self::Get;
    }

    public function isModifying(): bool {
        return in_array($this, [self::Post, self::Put, self::Delete]);
    }
}

$method = HttpMethod::Post;
echo "Method: {$method->value}\n";           // POST
echo "Safe? " . ($method->isSafe() ? 'yes' : 'no') . "\n";   // no
echo "Modifying? " . ($method->isModifying() ? 'yes' : 'no') . "\n"; // yes

Traits 🧩

PHP only supports single inheritance — a class can extend only one parent. But sometimes you need to share functionality across classes that don't share a common ancestor. Traits solve this: they're reusable bundles of methods that any class can use, effectively "copy-pasting" the methods into the class at compile time.

A trait is declared with the trait keyword and used with the use keyword inside a class. You can use multiple traits: use TraitA, TraitB;. If two traits define a method with the same name, PHP throws a fatal error — resolve it with insteadof (pick one) or as (rename the conflicting method).

Traits can define abstract methods that the using class must implement, and they can compose other traits. Properties in traits work the same as class properties. Think of traits as horizontal code reuse (across classes at the same level) vs. inheritance which is vertical (parent to child).

Exception Hierarchy ⚠️

PHP's exception system is built on the Throwable interface, which splits into two branches:

  • Exception — expected errors your code should anticipate and handle. Includes RuntimeException, InvalidArgumentException, LogicException, and many more.
  • Error — serious problems that usually indicate bugs in your code. Includes TypeError, ParseError, ArgumentCountError. These are harder to recover from.

Custom exceptions extend Exception (or a more specific subclass). They let you create domain-specific error types that carry meaningful context — like a ValidationException that bundles all field errors together.

Always order catch blocks from most specific to most general. PHP matches the first block that fits, so if you put Exception first, it will catch everything and the specific handlers below it become unreachable. The finally block always executes — whether an exception was thrown, caught, or no exception occurred at all. 

<?php
class ValidationException extends \Exception {
    private array $errors;

    public function __construct(array $errors) {
        $this->errors = $errors;
        $message = "Validation failed: " . implode(", ", array_keys($errors));
        parent::__construct($message);
    }

    public function getErrors(): array {
        return $this->errors;
    }
}

class NotFoundException extends \RuntimeException {
    public function __construct(string $resource, mixed $id) {
        parent::__construct("{$resource} with ID '{$id}' not found");
    }
}

Sessions & Cookies 🍪

HTTP is a stateless protocol — each request is independent, and the server forgets you the moment it sends a response. Sessions and cookies are the two mechanisms PHP uses to maintain state across requests.

A session stores data on the server side. When a session starts, PHP creates a unique ID, sends it to the browser as a cookie, and stores the associated data in a file (or other storage) on the server. On the next request, the browser sends that cookie back, PHP finds the session data, and $_SESSION is populated. Session data is larger, more secure, and invisible to the user.

A cookie stores data on the client (browser) side. The server sends it via the setcookie() function, and the browser includes it in every subsequent request to that domain. Cookies are small (4KB limit), the user can inspect and modify them, and they persist across browser sessions if you set an expiry date.

Security matters: always call session_start() before any output (even a space before <?php). Set httponly (prevents JavaScript access), secure (HTTPS only), and samesite (CSRF protection) flags on cookies.

<?php
class UserRepository {
    public function __construct(private PDO $pdo) {}

    public function findById(int $id): ?array {
        $stmt = $this->pdo->prepare("SELECT * FROM users WHERE id = :id");
        $stmt->execute(['id' => $id]);
        $user = $stmt->fetch();
        return $user ?: null;
    }

    public function findByEmail(string $email): ?array {
        $stmt = $this->pdo->prepare("SELECT * FROM users WHERE email = :email");
        $stmt->execute(['email' => $email]);
        return $stmt->fetch() ?: null;
    }

    public function create(string $name, string $email, string $role = 'user'): int {
        $stmt = $this->pdo->prepare(
            "INSERT INTO users (name, email, role) VALUES (:name, :email, :role)"
        );
        $stmt->execute(compact('name', 'email', 'role'));
        return (int) $this->pdo->lastInsertId();
    }

    public function update(int $id, array $data): bool {
        $fields = array_map(fn($col) => "$col = :$col", array_keys($data));
        $sql = "UPDATE users SET " . implode(', ', $fields) . " WHERE id = :id";
        $data['id'] = $id;
        return $this->pdo->prepare($sql)->execute($data) > 0;
    }

    public function delete(int $id): bool {
        return $this->pdo->prepare("DELETE FROM users WHERE id = :id")
            ->execute(['id' => $id]) > 0;
    }

        $allowed = ['name', 'email', 'created_at'];
        $col = in_array($orderBy, $allowed) ? $orderBy : 'name';
        return $this->pdo->query("SELECT * FROM users ORDER BY $col")->fetchAll();
    }

Attributes (PHP 8.0+) 🆕

Attributes are PHP 8.0's replacement for PHP doc-block annotations like @Route, @Inject, or @ORM\Column. Annotations were comments — PHP never parsed them. Attributes are structured, native syntax that PHP actually understands and can read at runtime via the Reflection API.

The syntax uses #[AttributeName(args)] placed directly before classes, methods, properties, functions, or parameters. You define an attribute by creating a class and marking it with the #[Attribute] built-in. PHP 8.3 added #[Override] (enforces that a method actually overrides a parent), and #[Deprecated] (flags methods/classes as deprecated).

Attributes can target specific code structures: classes, methods, properties, functions, or parameters. You control this with flags like Attribute::TARGET_CLASS, Attribute::TARGET_METHOD, and Attribute::TARGET_PROPERTY. Combine them with bitwise OR (|) to allow multiple targets. 

<?php
#[Attribute(Attribute::TARGET_CLASS | Attribute::TARGET_METHOD)]
class Route {
    public function __construct(
        public string $path,
        public array $methods = ['GET']
    ) {}
}

#[Attribute(Attribute::TARGET_PROPERTY)]
class Column {
    public function __construct(
        public string $name,
        public string $type = 'string'
    ) {}
}

#[Route('/api/users', methods: ['GET', 'POST'])]
class UserController {
    #[Route('/api/users/{id}', methods: ['GET', 'PUT', 'DELETE'])]
    public function getUser(int $id): array {
        return ['id' => $id];
    }

    #[Route('/api/users', methods: ['POST'])]
    public function createUser(): void { /* ... */ }
}

// Reading attributes via Reflection

$attrs = $ref->getAttributes(Route::class);
$route = $attrs[0]->newInstance();
echo $route->path; // /api/users

Constructor Property Promotion 🚀

Constructor property promotion is a PHP 8.0 shorthand that collapses property declaration, constructor parameter, and assignment into a single line. Add a visibility modifier (public, protected, private) directly to the constructor parameter, and PHP automatically creates and assigns the property.

This works with readonly, union types, nullable types, and default values. It eliminates one of the most common boilerplate patterns in PHP classes — the "declare property, accept in constructor, assign to property" dance that took 4-7 lines per property. 

<?php
// BEFORE (PHP 7.4 — 7 lines)
class PointOld {
    public float $x;
    public float $y;
    public function __construct(float $x, float $y) {
        $this->x = $x;
        $this->y = $y;
    }
}

// AFTER (PHP 8.0+ — 3 lines)
class Point {
    public function __construct(
        public readonly float $x,
        public readonly float $y,
    ) {}

    public function distanceTo(self $other): float {
        return sqrt(($this->x - $other->x) ** 2 + ($this->y - $other->y) ** 2);
    }
}

$p1 = new Point(0, 0);
$p2 = new Point(3, 4);
echo $p1->distanceTo($p2); // 5

Match Expression 🎯

The match expression is PHP 8.0's modern replacement for switch. Key differences: match uses strict comparison (===), has no fallthrough, is an expression (it returns a value), and arms are separated by commas. Multiple values per arm are supported: 1, 2, 3 => "small".

A default arm is required if not all cases are covered — otherwise PHP throws an UnhandledMatchError. You can match on non-scalar values, use match(true) as a pattern for complex conditions (like a series of if/elseif), and nest match expressions. 

<?php
// Match as expression
$status = 'paid';
$paymentStatus = match($status) {
    'paid', 'completed' => '✅',
    'pending' => '⏳',
    'failed', 'refunded' => '❌',
    default => '❓',
};
echo "Status: $paymentStatus\n";

// Match with complex conditions
$age = 25;
$result = match(true) {
    $age < 13 => 'child',
    $age < 18 => 'teenager',
    $age < 65 => 'adult',
    default => 'senior',
};
echo "Category: $result\n";

// Nested match — grade calculator
$score = 92;
$grade = match(true) {
    $score >= 90 => match($score >= 97) { true => 'A+', false => 'A' },
    $score >= 80 => 'B',
    $score >= 70 => 'C',
    default => 'F',
};
echo "Score: $score => Grade: $grade";
Status: ✅
Category: adult
Score: 92 => Grade: A

Unlike switch, match is strict. switch(0) would match case false because it uses loose comparison (==). match(0) will not match false — it requires an exact === match. This eliminates an entire category of subtle bugs.

Since match is an expression, you can use it directly in assignments, return statements, array definitions, or function arguments without temporary variables: 

<?php

];

Nullsafe Operator 💧

The nullsafe operator ?-> (PHP 8.0) short-circuits an entire method or property chain when it encounters null. Instead of writing nested if checks for every level of a deep object graph, you write $user?->getAddress()?->getCity()?->getName(). If any part returns null, the entire expression evaluates to null — no error thrown.

This is different from the null coalescing operator ??. The ?? operator checks whether a value is null. The ?-> operator checks whether an object exists before calling a method or accessing a property on it. Use ?-> for method/property chains, and ?? to provide a fallback value. 

<?php
class Address {
    public function __construct(public ?string $city = null) {}
}

class User {
    public function __construct(public ?Address $address = null) {}
}

$users = [
    new User(new Address("New York")),
    new User(new Address()),     // city is null
    new User(),                  // address is null
];

foreach ($users as $i => $user) {
    // Without nullsafe: if ($user && $user->getAddress() && ...)
    // With nullsafe + ?? fallback:
    $city = $user->address?->city ?? "Unknown";
    echo "User $i: $city\n";
}
User 0: New York
User 1: Unknown
User 2: Unknown

The nullsafe operator is especially useful in frameworks where deeply nested objects are common — think doctrine entities with relationships, or configuration objects with optional sections. Note that you cannot use ?-> for method chaining where you need to continue the chain (like $obj?->method()->other()) — the second call will fail if the first returned null. The short-circuit stops the entire chain. 

<?php
class Country {
    public function __construct(public string $name = 'Unknown') {}
}

class State {
    public function __construct(public ?Country $country = null) {}
}

class City {
    public function __construct(public ?State $state = null) {}
}

class Person {
    public function __construct(public ?City $city = null) {}
}

$people = [
    new Person(new City(new State(new Country('USA')))),
    new Person(new City(new State())),          // country is null
    new Person(new City()),                     // state is null
    new Person(),                               // city is null
];

foreach ($people as $i => $person) {
    // Deep chain with nullsafe — safe traversal
    $country = $person->city?->state?->country?->name ?? 'N/A';
    echo "Person $i country: $country\n";
}

// Comparison: what we'd need WITHOUT nullsafe
$person = $people[0];
if ($person !== null
    && $person->city !== null
    && $person->city->state !== null
    && $person->city->state->country !== null
) {
    echo $person->city->state->country->name; // USA
}

Person 1 country: N/A
Person 2 country: N/A
Person 3 country: N/A
USA

Readonly Properties & Classes 🔒

Readonly properties (PHP 8.1) can only be set once — in the constructor or directly if not promoted. After initialization, any attempt to modify them throws a fatal error. This enforces immutability at the language level, making your value objects and DTOs genuinely immutable without extra boilerplate.

Readonly classes (PHP 8.2) take it further: marking a class as readonly class makes every property automatically readonly. You cannot have readonly properties without a type declaration — the type is required so PHP knows the property has been initialized.

First-Class Callable Syntax 🔴

First-class callable syntax (PHP 8.1) lets you create a Closure from any function or method reference using functionName(...). This replaces the verbose Closure::fromCallable('functionName') with a clean, intuitive syntax. It works with regular functions, instance methods, static methods, and even built-in PHP functions.

The syntax is always the callable name followed by (...) — an empty argument list with the spread operator. This creates a Closure object you can pass to array_map, array_filter, usort, or any function that accepts callables. 

<?php
// Function to closure
function greet(string $name): string {
    return "Hello, $name!";

    public static function slugify(string $text): string {

$words = ['Hello World', 'PHP 8.4 is Great', '  Extra   Spaces  '];

Closures Deep Dive 💰

PHP has two kinds of anonymous functions: anonymous functions (function() { }) and arrow functions (fn() =>). Arrow functions auto-capture variables from the parent scope by value (a snapshot at definition time). Anonymous functions require explicit use to capture variables, but can capture by reference (use (&$var)).

Closure::bind() lets you change the $this context and binding scope of a closure — this is how you can access private properties from outside a class. Closure::fromCallable() converts any callable (string, array, closure) into a proper Closure object. 

<?php
// Arrow vs Anonymous: capture difference
$counter = 0;

// Arrow — captures VALUE (snapshot at definition time)
$arrow = fn() => $counter;
$counter = 5;
echo "Arrow: " . $arrow() . "\n";  // 0 (captured original value)

// Anonymous with use — captures by reference
$counter = 0;
$anon = function() use (&$counter) {
    return $counter;
};
$counter = 5;
echo "Anonymous ref: " . $anon() . "\n";  // 5 (sees current value)

// Modifying via reference capture
$total = 0;
$adder = function(int $n) use (&$total) {
    $total += $n;
};
$adder(10);
$adder(20);
$adder(30);
echo "Total: $total\n";  // 60
Arrow: 0
Anonymous ref: 5
Total: 60

Closure::bind() is a powerful reflection tool. It lets you create a closure that runs as if it were a method of a specific class, giving it access to private properties. The three arguments are: the closure, the object to bind as $this, and the class scope (which determines visibility access). 

<?php
// Closure::bind — accessing private properties
class Secret {
    private string $data = "hidden treasure";
    private string $key = "abc123";
}

// Create a closure that reads $this->data
$reader = function() {
    return $this->data;
};

// Bind it to a Secret instance with Secret's scope
$bound = Closure::bind($reader, new Secret(), Secret::class);
echo "Read: " . $bound() . "\n";  // hidden treasure

// Writer — modifying private properties
$writer = function(string $value) {
    $this->data = $value;
};
$boundWriter = Closure::bind($writer, $obj = new Secret(), Secret::class);
$boundWriter("new secret");
echo "After write: " . Closure::bind($reader, $obj, Secret::class)() . "\n";

// Higher-order function: apply a transformation with closure
function withLock(callable $fn, mixed &$value): mixed {
    $copy = $value;
    $result = $fn($copy);
    return $result;
}

$price = 100;

$withDiscount = withLock(fn($p) => $p * 0.9, $price);

Generators ⚡

Generator functions use yield instead of return to produce a sequence of values lazily — one at a time, not all loaded into memory at once. When a generator yields a value, it pauses execution and saves its state. On the next iteration, it resumes exactly where it left off.

A generator function returns a Generator object (which implements Iterator). This makes generators usable with foreach. Use yield from to delegate to another generator or iterable — this flattens nested generators. For large datasets (CSV files, database results, API pagination), generators are dramatically more memory-efficient than building arrays. 

<?php
// Simple generator
function rangeGenerator(int $start, int $end): \Generator {
    for ($i = $start; $i <= $end; $i++) {
        yield $i;
    }
}

foreach (rangeGenerator(1, 5) as $num) {
    echo "$num ";
}
// Output: 1 2 3 4 5

// Generator that yields key-value pairs
function wordLengths(array $words): \Generator {
    foreach ($words as $word) {
        yield $word => strlen($word);
    }
}

echo "\nWord lengths:\n";
foreach (wordLengths(['apple', 'banana', 'cherry', 'date']) as $word => $len) {
    echo "  $word: $len\n";
}

// yield from — delegating generators
function combinedGenerator(): \Generator {
    yield from [1, 2, 3];
    yield from rangeGenerator(4, 6);
    yield from ['a', 'b'];
}

echo "\nCombined: " . implode(', ', [...combinedGenerator()]);
1 2 3 4 5
Word lengths:
  apple: 5
  banana: 6
  cherry: 6
  date: 4
Combined: 1, 2, 3, 4, 5, 6, a, b

Generators shine when processing large data. Instead of loading a million rows into an array (which could exhaust memory), a generator yields one row at a time. The caller processes each row and discards it before the next one is generated. Memory usage stays constant regardless of dataset size.

Fibers (PHP 8.1+) 🆕

Fibers are PHP 8.1's lightweight coroutine mechanism. A Fiber represents a pauseable, resumable function. You create one with new Fiber(callable), start it with $fiber->start(), pause it from inside with Fiber::suspend($value), and resume it from outside with $fiber->resume($value) or throw an exception into it with $fiber->throw($e).

Fibers are NOT threads — PHP remains single-threaded. Fibers provide cooperative multitasking: the fiber chooses when to yield control back to the main context. The primary use case is async I/O without callback hell — database queries, HTTP requests, and file operations can be written in a linear style while the underlying implementation handles the async scheduling. 

<?php
$fiber = new Fiber(function(): void {
    $value = Fiber::suspend('fiber started');
    echo "Fiber received: $value\n";

    try {
        $value2 = Fiber::suspend('fiber resumed again');
    } catch (Throwable $e) {
        echo "Fiber caught: " . $e->getMessage() . "\n";
    }

    echo "Fiber done\n";
});

// Start the fiber — returns suspended value
$result = $fiber->start();
echo "Main received: $result\n";

// Resume with a value
$result = $fiber->resume('hello from main');
echo "Main received: $result\n";

// Throw exception into fiber
$fiber->throw(new RuntimeException('error from main'));
Main received: fiber started
Fiber received: hello from main
Main received: fiber resumed again
Fiber caught: error from main
Fiber done

Think of a Fiber as a separate call stack that can be switched to and from. When you call Fiber::suspend(), execution jumps back to wherever start() or resume() was called. When you call resume(), execution jumps back into the fiber right after the suspend() call. The value passed to resume() becomes the return value of suspend() inside the fiber. 

<?php

Custom Error Handlers 🔧

PHP provides three global handlers for controlling error behavior: set_error_handler() catches PHP errors (warnings, notices, deprecations) and lets you convert them to exceptions. set_exception_handler() is the last-resort handler for uncaught exceptions. register_shutdown_function() runs after script execution ends — including after fatal errors — making it the only way to catch fatal errors.

The standard production pattern is: convert all errors to ErrorExceptions via set_error_handler, set a set_exception_handler that logs and returns a clean error page, and use register_shutdown_function to catch any fatal errors that slip through. 

<?php
// Convert all errors to exceptions

    if (!(error_reporting() & $severity)) {
        return; // Error not in current reporting level
    }
    throw new ErrorException($message, 0, $severity, $file, $line);
});

// Catch all uncaught exceptions
set_exception_handler(function(Throwable $e): void {
    error_log("Uncaught: {$e->getMessage()} in {$e->getFile()}:{$e->getLine()}");
    echo "ERROR: An internal error occurred. Please try again.\n";
});

// Cleanup on shutdown (catches fatal errors)
register_shutdown_function(function(): void {
    $error = error_get_last();
    if ($error && in_array($error['type'], [E_ERROR, E_PARSE, E_CORE_ERROR])) {
        error_log("Fatal: {$error['message']} in {$error['file']}:{$error['line']}");
        echo "FATAL ERROR: The application crashed.\n";
    }
});

Property hooks are PHP 8.4's most transformative feature. They define get/set behavior directly on properties, replacing the boilerplate of explicit getter/setter methods. Asymmetric visibility (PHP 8.4) lets you set different access levels for reading and writing a property. The syntax public private(set) means everyone can read the property, but only the class itself can write to it. The first modifier is the get visibility, the second (in parentheses) is the set visibility.

Common patterns: public private(set) for immutable-from-outside properties (read-only to external code, writable inside the class), public protected(set) for properties children can modify but external code cannot. <?php

Zend Engine & Internals

The Zend Engine is PHP's execution engine — the equivalent of the JVM for Java or V8 for JavaScript. Every PHP script passes through a multi-stage compilation pipeline before any code actually runs. Understanding this pipeline is the foundation for performance tuning, writing C extensions, and debugging seemingly mysterious bottlenecks.

The pipeline flows as: PHP Source → Lexer (tokenizes into tokens like T_VARIABLE, T_STRING) → Parser (builds an Abstract Syntax Tree / AST) → Compiler (converts AST to opcodes — low-level instructions for the VM) → Executor (runs opcodes sequentially on the Zend VM). Without OPcache, this entire pipeline runs on every single request. OPcache caches the compiled opcodes in shared memory, skipping lexing, parsing, and compilation entirely.

Internally, every PHP value is represented as a zval — a struct containing the value, type info, a reference count, and an is_ref flag. When you write $b = $a, both variables point to the same zval with refcount=2 (copy-on-write). Functions defined in C extensions receive arguments through zend_parse_parameters(), which type-checks and extracts each argument from the calling frame into C variables.

JIT Compiler

PHP 8.0 introduced a Just-In-Time (JIT) compiler that translates hot PHP opcode paths into native machine code at runtime. While OPcache eliminates the compilation overhead, JIT goes further — it eliminates the interpretation overhead for frequently-executed code paths, potentially delivering 10–15x speedups on CPU-bound workloads.

The JIT operates in two modes: Tracing JIT (watches execution paths at runtime, identifies hot loops and frequently-called functions, then compiles those specific paths to machine code) and Function JIT (compiles entire functions from opcodes to machine code). Tracing JIT is almost always faster because it can optimize across function call boundaries and eliminate dead branches based on observed runtime data. The opcache.jit 4-digit configuration controls this: first digit 1 = tracing, 2 = function, 0 = off.

JIT helps most with CPU-bound work: numeric calculations, recursive algorithms, tight loops, string processing. Memory Management

PHP's memory model is built on copy-on-write (COW) semantics. When you assign $b = $a, both variables point to the same underlying zval struct in memory — the refcount increments to 2, but no data is copied. Only when you modify $b does the engine allocate a new zval and copy the data. This makes passing arrays and strings to functions extremely cheap when they are read-only.

The zval struct is the heart of PHP's memory system. Each zval contains: the actual value (stored as a union — 8 bytes), type info (IS_STRING, IS_ARRAY, IS_LONG, etc.), a reference count (how many variables/arrays point to this zval), and an is_ref flag (set when & references are used). When refcount hits 0 via unset() or variable going out of scope, the zval is immediately freed.

PHP's garbage collector specifically handles circular references — situations where object A references B and B references A. Without the GC, these objects would never be freed because refcount never reaches 0. The GC runs a cycle detection algorithm (mark-and-sweep) and can be triggered manually with gc_collect_cycles(). Use gc_enable() / gc_disable() to control automatic collection. Functions like memory_get_usage() return the memory actually used by PHP variables, while memory_get_usage(true) returns the total memory allocated from the system (which is always larger due to allocator overhead).

OPcache

OPcache is a shared memory cache for compiled PHP bytecode (opcodes). It eliminates the most expensive part of PHP's execution pipeline: on every request, PHP normally lexes source code into tokens, parses tokens into an AST, then compiles the AST into opcodes. OPcache caches the final opcodes in shared memory, so subsequent requests skip directly to execution — a massive performance win, especially for large frameworks like Laravel or Symfony that load hundreds of files.

Key configuration directives: opcache.enable=1 activates the cache (always enable in production), opcache.enable_cli=1 enables it for CLI scripts (useful for long-running workers), opcache.memory_consumption=256 sets the shared memory pool size in MB, and opcache.max_accelerated_files=20000 defines the maximum number of PHP files OPcache will cache (must be larger than your total file count). In production, set opcache.validate_timestamps=0 to disable file-change checking (use opcache_invalidate() or restart PHP-FPM when deploying), and opcache.revalidate_freq=0 to never auto-revalidate.

Preloading (PHP 7.4+) goes even further: opcache.preload=/path/to/preload.php loads specified classes, interfaces, and functions into shared memory at PHP-FPM startup. This means every worker process shares the same preloaded code — no per-request loading overhead. Preloaded classes are available instantly and cannot be unloaded until the process restarts.

Stream Wrappers

Stream wrappers are one of PHP's most powerful and underused features. Fibers Deep Dive

Building on the Fiber basics from the Advanced level, a deep dive into Fibers reveals their true power: implementing cooperative multitasking and event-driven architectures in PHP without callbacks. The pattern works by creating an event loop — a central loop that manages multiple Fibers, starting, suspending, and resuming them as I/O operations complete. Each Fiber suspends at I/O boundaries (waiting for a socket, a timer, a file read), and the event loop uses that suspension time to run other Fibers.

This is how async libraries like ReactPHP, Amp, and Swoole work under the hood. PHP Fibers (8.1+) provide the primitives to build these systems at the language level. The key concept is the suspension point: when a Fiber calls Fiber::suspend(), execution returns to the caller (the event loop). The event loop can then resume the Fiber later with new data. This enables multiplexing — running multiple I/O-bound tasks concurrently within a single thread, without the overhead of OS threads or processes.

Fiber stack management is important: each Fiber gets its own call stack (default size is configurable via fiber.stack_size in php.ini). Stack overflow occurs if a Fiber's call chain exceeds this limit. Be careful with recursive algorithms inside Fibers. 

<?php
// Simple event loop implementation with Fibers
class EventLoop {
    private array $tasks = [];
    private array $timers = [];
    private bool $running = false;

    public function defer(callable $callback): Fiber {
        $fiber = new Fiber($callback);
        $this->tasks[] = $fiber;
        return $fiber;
    }

    public function setTimeout(callable $callback, int $ms): void {
        $this->timers[] = [
            'time' => microtime(true) + ($ms / 1000),
            'callback' => $callback,
        ];
    }

    public function run(): void {
        $this->running = true;

        while ($this->running && (!empty($this->tasks) || !empty($this->timers))) {
            // Run and manage ready tasks
            $pending = [];
            foreach ($this->tasks as $fiber) {
                try {
                    if (!$fiber->isStarted()) {
                        $fiber->start();
                    } else {
                        $fiber->resume();
                    }
                } catch (\Throwable $e) {
                    echo "Task error: " . $e->getMessage() . "\n";
                }

                if (!$fiber->isTerminated()) {
                    $pending[] = $fiber;
                }
            }
            $this->tasks = $pending;

            // Check and fire ready timers
            $now = microtime(true);
            $fired = [];
            $remaining = [];
            foreach ($this->timers as $timer) {
                if ($timer['time'] <= $now) {
                    $fired[] = $timer;
                } else {
                    $remaining[] = $timer;
                }
            }
            $this->timers = $remaining;
            foreach ($fired as $timer) {
                $timer['callback']();
            }

            usleep(1000); // 1ms sleep to prevent CPU spinning
        }
    }

    public function stop(): void {
        $this->running = false;
    }
}

// Usage: cooperative multitasking

    echo "[Task 1] Started\n";
    Fiber::suspend(); // Yield control back to event loop
    echo "[Task 1] Resumed\n";
    Fiber::suspend(); // Suspend again
    echo "[Task 1] Finished\n";
});

$loop->defer(function () {
    echo "[Task 2] Running immediately\n";
});

    echo "[Timer] Fired after 50ms\n";
}, 50);

FFI (Foreign Function Interface)

FFI (Foreign Function Interface), introduced in PHP 7.4, lets you call C library functions directly from PHP — no extension compilation, no PECL, no phpize. You declare C function signatures and struct definitions in a string, optionally specify a shared library (.so on Linux, .dylib on macOS, .dll on Windows), and call them as if they were PHP methods. This opens up the entire C ecosystem to PHP scripts.

The primary API: FFI::cdef(string $declarations, ?string $library) parses C declarations and links to a library. FFI::load(string $filename) loads declarations from a pre-compiled C header file (more efficient for large declarations). For memory management: FFI::new($type) allocates a C struct/variable, FFI::free($ptr) frees it, FFI::addr($var) gets a pointer to a variable, and FFI::cast($type, $ptr) casts between pointer types. FFI is slower than native C extensions (due to marshaling overhead) but requires zero compilation — ideal for prototyping, testing, and scripting around C libraries.

Security Hardening

Security hardening goes beyond basic prepared statements and input filtering. At the expert level, you need a comprehensive defense-in-depth strategy: CSRF protection via synchronizer token pattern, Content Security Policy (CSP) headers to prevent XSS, context-aware output encoding (HTML, JavaScript, URL, CSS each require different encoding), secure session configuration, php.ini hardening, and robust file upload validation.

CSRF (Cross-Site Request Forgery) protection works by embedding a cryptographically random token in every HTML form and verifying it on submission. The token is generated server-side, stored in the session, and included as a hidden field. On form submission, the server compares the submitted token against the session token using hash_equals() (timing-safe comparison to prevent timing attacks). CSP headers restrict which scripts, styles, images, and other resources the browser is allowed to load — the strongest defense against XSS.

PHP-level hardening includes: open_basedir (restricts file access to specific directories), disable_functions (disables dangerous functions like exec, shell_exec, passthru, system, eval), expose_php=Off (removes the X-Powered-By header), and allow_url_include=Off (prevents remote file inclusion). Session security: session.cookie_httponly=1 (prevents JS access to cookies), session.cookie_secure=1 (HTTPS only), session.cookie_samesite=Strict (prevents CSRF via cross-site requests), and session.use_strict_mode=1 (rejects uninitialized session IDs). 

<?php
// CSRF Token implementation (complete, production-ready)
class CsrfProtection {
    public static function generate(): string {
        if (session_status() === PHP_SESSION_NONE) session_start();
        // bin2hex(random_bytes(32)) = 64-char hex string
        $token = bin2hex(random_bytes(32));
        $_SESSION['csrf_token'] = $token;
        $_SESSION['csrf_token_time'] = time();
        return $token;
    }

    public static function validate(string $token): bool {
        if (session_status() === PHP_SESSION_NONE) session_start();
        if (empty($_SESSION['csrf_token'])) return false;

        // Optional: expire tokens after 1 hour
        if (isset($_SESSION['csrf_token_time'])) {
            if ((time() - $_SESSION['csrf_token_time']) > 3600) {
                self::generate(); // Rotate expired token
                return false;
            }
        }

        // hash_equals prevents timing attacks
        $valid = hash_equals($_SESSION['csrf_token'], $token);
        self::generate(); // Rotate token after each use
        return $valid;
    }

    public static function field(): string {
        $token = self::generate();
        return '<input type="hidden" name="_token" value="'
            . htmlspecialchars($token, ENT_QUOTES, 'UTF-8') . '">';
    }

    public static function metaTag(): string {
        $token = self::generate();
        return '<meta name="csrf-token" content="' . htmlspecialchars($token) . '">';
    }
}

function safeUpload(array $file, string $uploadDir): string {

    $allowedExt = ['jpg', 'jpeg', 'png', 'gif', 'webp'];

        throw new RuntimeException("Invalid file type: $detectedMime");
    }

    if ($file['size'] > $maxSize) {
        throw new RuntimeException("File exceeds 2MB limit");
    }

    // Validate upload was legit (not a file path traversal attack)
    if (!is_uploaded_file($file['tmp_name'])) {
        throw new RuntimeException("Invalid upload");
    }

    // Generate random filename to prevent enumeration
    $ext = array_search($detectedMime, $allowed, true);
    $ext = $allowedExt[$ext] ?? 'bin';
    $name = bin2hex(random_bytes(16)) . '.' . $ext;

    // Store outside webroot if possible
    $dest = rtrim($uploadDir, '/') . '/' . $name;
    if (!move_uploaded_file($file['tmp_name'], $dest)) {
        throw new RuntimeException("Failed to move uploaded file");
    }

    // Set restrictive permissions
    chmod($dest, 0644);
    return $name;
}

Dependency Injection

Dependency Injection (DI) is a design pattern where objects receive their dependencies from an external source (a container or factory) rather than creating them internally. This decouples classes from their dependencies, making code testable (inject mocks), flexible (swap implementations), and maintainable. DI is the foundation of modern PHP frameworks — Laravel's service container, Symfony's DependencyInjection component, and PSR-11 (Psr\Container\ContainerInterface) all implement this pattern.

An IoC (Inversion of Control) Container maps interfaces to concrete implementations and resolves dependency graphs automatically. When you request $container->get(Cache::class), the container inspects Cache's constructor, resolves its dependencies recursively, and constructs the entire object graph. Service lifetimes control instance reuse: singleton (one shared instance for the entire application lifetime) versus transient (a fresh instance every time you resolve). Autowiring uses PHP's Reflection API to inspect constructor type hints and automatically resolve dependencies without explicit binding configuration. 

<?php
// Simple DI Container with singleton support
class Container {
    /** @var array<string, array{concrete: \Closure|string, singleton: bool}> */
    private array $bindings = [];
    /** @var array<string, object> */
    private array $singletons = [];
    /** @var array<string, object> */
    private array $instances = [];

    public function bind(string $abstract, \Closure|string $concrete, bool $singleton = false): void {
        $this->bindings[$abstract] = [
            'concrete' => $concrete,
            'singleton' => $singleton,
        ];
    }

    public function singleton(string $abstract, \Closure|string $concrete): void {
        $this->bind($abstract, $concrete, true);
    }

    public function instance(string $abstract, object $instance): void {
        $this->instances[$abstract] = $instance;
    }

    public function make(string $abstract): object {
        // Check for explicit instance
        if (isset($this->instances[$abstract])) {
            return $this->instances[$abstract];
        }

        // Return cached singleton
        if (isset($this->singletons[$abstract])) {
            return $this->singletons[$abstract];
        }

        // Resolve the concrete
        $concrete = $this->bindings[$abstract]['concrete'] ?? $abstract;

        if ($concrete instanceof \Closure) {
            $instance = $concrete($this);
        } else {
            $instance = $this->resolve($concrete);
        }

        // Cache if singleton
        if ($this->bindings[$abstract]['singleton'] ?? false) {
            $this->singletons[$abstract] = $instance;
        }

        return $instance;
    }

    public function has(string $abstract): bool {
        return isset($this->bindings[$abstract])
            || isset($this->singletons[$abstract])
            || isset($this->instances[$abstract])
            || class_exists($abstract);
    }

    // Simple reflection-based autowiring
    private function resolve(string $class): object {
        $ref = new \ReflectionClass($class);
        $constructor = $ref->getConstructor();

        if ($constructor === null) {
            return $ref->newInstance();
        }

        $params = [];
        foreach ($constructor->getParameters() as $param) {
            $type = $param->getType();
            if ($type instanceof \ReflectionNamedType && !$type->isBuiltin()) {
                $params[] = $this->make($type->getName());
            } elseif ($param->isDefaultValueAvailable()) {
                $params[] = $param->getDefaultValue();
            } else {
                throw new \RuntimeException(
                    "Cannot resolve parameter \${$param->getName()} in {$class}"
                );
            }
        }

        return $ref->newInstanceArgs($params);
    }
}

Microservices Patterns

PHP excels in microservices architectures thanks to modern runtimes like Swoole and RoadRunner that enable long-running PHP processes (eliminating per-request boot overhead). Key PHP microservices frameworks include Slim (lightweight REST), Swoole (async, coroutine-based HTTP server), RoadRunner (Go-powered application server that keeps PHP workers alive between requests), and ReactPHP (event-driven, non-blocking I/O). For inter-service communication, choose between REST (simple, universal), gRPC (fast binary protocol with code generation), and GraphQL (flexible queries from the client).

Critical microservices patterns include: API Gateway (single entry point routing to multiple services), Service Discovery (dynamic service registration via Consul or etcd), Circuit Breaker (prevent cascading failures when a downstream service is down), Saga (distributed transactions across services — compensating actions instead of ACID), and Message Queues (async communication via Redis pub/sub, RabbitMQ, or Kafka). The Circuit Breaker pattern is essential: it monitors call failures and "opens" the circuit (rejects calls immediately) after a threshold, then "half-opens" after a timeout to test if the service recovered. 

<?php
// Circuit Breaker pattern — prevents cascading failures
class CircuitBreaker {
    private enum State {
        case Closed;   // Normal operation — calls go through
        case Open;     // Failing — calls rejected immediately
        case HalfOpen; // Testing — allow one call to test recovery
    }

    private State $state = State::Closed;
    private int $failures = 0;
    private int $successes = 0;
    private ?\DateTimeImmutable $lastFailure = null;
    private readonly int $failureThreshold;
    private readonly int $resetTimeout;
    private readonly int $halfOpenSuccessThreshold;

    public function __construct(
        int $failureThreshold = 5,
        int $resetTimeout = 30,
        int $halfOpenSuccessThreshold = 3
    ) {
        $this->failureThreshold = $failureThreshold;
        $this->resetTimeout = $resetTimeout;
        $this->halfOpenSuccessThreshold = $halfOpenSuccessThreshold;
    }

    public function call(callable $operation, ?callable $fallback = null): mixed {
        return match ($this->state) {
            self::State::Closed => $this->attempt($operation, $fallback),
            self::State::Open => $this->shouldRetry()
                ? $this->attempt($operation, $fallback)
                : ($fallback !== null
                    ? $fallback()
                    : throw new \RuntimeException('Circuit is OPEN — service unavailable')),
            self::State::HalfOpen => $this->attempt($operation, $fallback),
        };
    }

    private function attempt(callable $op, ?callable $fallback): mixed {
        try {
            $result = $op();
            $this->onSuccess();
            return $result;
        } catch (\Throwable $e) {
            $this->onFailure();
            if ($fallback !== null) {
                return $fallback();
            }
            throw $e;
        }
    }

    private function onSuccess(): void {
        $this->failures = 0;

        if ($this->state === self::State::HalfOpen) {
            $this->successes++;
            if ($this->successes >= $this->halfOpenSuccessThreshold) {
                $this->state = self::State::Closed;
                $this->successes = 0;
            }
        }
    }

    private function onFailure(): void {
        $this->failures++;
        $this->lastFailure = new \DateTimeImmutable();

        if ($this->state === self::State::Closed
            && $this->failures >= $this->failureThreshold
        ) {
            $this->state = self::State::Open;
        } elseif ($this->state === self::State::HalfOpen) {
            $this->state = self::State::Open; // Failed during test
        }
    }

    private function shouldRetry(): bool {
        if ($this->lastFailure === null) return false;
        $elapsed = time() - $this->lastFailure->getTimestamp();
        if ($elapsed >= $this->resetTimeout) {
            $this->state = self::State::HalfOpen;
            $this->successes = 0;
            return true;
        }
        return false;
    }

    public function getState(): string {
        return $this->state->name;
    }

    public function getFailureCount(): int {
        return $this->failures;
    }
}

Custom PHP Extensions in C

Writing custom PHP extensions in C is the ultimate performance optimization — compiled C code runs at native speed, bypassing the Zend VM entirely. Extensions are the mechanism behind PECL packages, PHP's built-in functions (strlen, array_push, json_encode), and even the SPL classes. You write a C extension when: performance-critical code is too slow in PHP, you need to integrate a C/C++ library, or you are researching PHP internals.

The workflow: run ext_skel --extname=myext to generate a skeleton, edit myext.c to add your functions, define them in the function table (zend_function_entry), compile with phpize && ./configure --enable-myext && make && make install, then add extension=myext.so to php.ini. Key C macros: PHP_FUNCTION(name) declares a PHP-callable function, zend_parse_parameters(ZEND_NUM_ARGS(), "type_spec", &vars) parses PHP arguments (type spec: s=string, l=long, d=double, z=zval, b=bool, a=array, |=optional), and RETURN_* macros return values (RETURN_STRING(s), RETURN_LONG(n), RETURN_DOUBLE(f), RETURN_BOOL(b), RETURN_NULL(), RETURN_THROWS()). 

/* myext.c — a simple PHP extension written in C */
#include "php.h"
#include "php_myext.h"
#include "string.h"

/* Declare our PHP function */
PHP_FUNCTION(add_numbers) {
    long a, b;

    /* Parse parameters: "ll" = two long (integer) arguments */
    if (zend_parse_parameters(ZEND_NUM_ARGS(), "ll", &a, &b) == FAILURE) {
        RETURN_THROWS();
    }

    RETURN_LONG(a + b);
}

/* Declare our PHP function: string_reverse (UTF-8 aware) */
PHP_FUNCTION(my_string_reverse) {
    char *input;
    size_t input_len;

    if (zend_parse_parameters(ZEND_NUM_ARGS(), "s", &input, &input_len) == FAILURE) {
        RETURN_THROWS();
    }

    /* Allocate output buffer (same length, reversed) */
    char *reversed = emalloc(input_len + 1);
    for (size_t i = 0; i < input_len; i++) {
        reversed[i] = input[input_len - 1 - i];
    }
    reversed[input_len] = '\0';

    /* Return string (copies to PHP zval, we keep ownership of buffer) */
    RETURN_STRINGL(reversed, input_len);
    efree(reversed);
}

/* Declare our PHP function: repeat_string */
PHP_FUNCTION(my_repeat_string) {
    char *input;
    size_t input_len;
    zend_long times;

    if (zend_parse_parameters(ZEND_NUM_ARGS(), "sl", &input, &input_len, &times) == FAILURE) {
        RETURN_THROWS();
    }

    if (times < 0) {
        php_error_docref(NULL, E_WARNING, "Negative repeat count");
        RETURN_EMPTY_STRING();
    }

    size_t result_len = input_len * times;
    char *result = emalloc(result_len + 1);
    for (zend_long i = 0; i < times; i++) {
        memcpy(result + (i * input_len), input, input_len);
    }
    result[result_len] = '\0';

    RETURN_STRINGL(result, result_len);
    efree(result);
}

/* Function table — maps PHP names to C functions */
static const zend_function_entry myext_functions[] = {
    PHP_FE(add_numbers, NULL)
    PHP_FE(my_string_reverse, NULL)
    PHP_FE(my_repeat_string, NULL)
    PHP_FE_END
};

/* Module entry */
zend_module_entry myext_module_entry = {
    STANDARD_MODULE_HEADER,
    "myext",                /* Extension name */
    myext_functions,        /* Function table */
    NULL,                   /* PHP_MINIT */
    NULL,                   /* PHP_MSHUTDOWN */
    NULL,                   /* PHP_RINIT */
    NULL,                   /* PHP_RSHUTDOWN */
    NULL,                   /* PHP_MINFO */
    NO_VERSION_YET,         /* Version */
    STANDARD_MODULE_PROPERTIES
};

Performance Profiling

Performance profiling is the systematic process of measuring where your PHP application spends its time and memory. The workflow is: measure (collect timing and memory data) → analyze (identify the slowest functions and highest-memory operations) → optimize (fix the bottleneck) → verify (measure again to confirm improvement). Never optimize without profiling — developer intuition about bottlenecks is notoriously wrong.

Available profiling tools: Xdebug Profiler (xdebug.profiler_enable=1, generates cachegrind-compatible files that can be analyzed with KCacheGrind, QCacheGrind, or WebGrind), XHProf/XHGui (lightweight profiler from Facebook/Meta with a web UI for comparing profiles), Blackfire.io (commercial profiler with automated performance tracking, free tier available), and PHP-FPM slow log (request_slowlog_timeout=5s logs any request exceeding 5 seconds). For quick-and-dirty profiling, microtime(true) checkpoints and memory_get_usage() are often sufficient. 

<?php
// Manual profiling helper — zero dependencies, works everywhere
class Profiler {
    private array $marks = [];
    private static ?self $instance = null;

    public static function start(string $name): void {
        self::$instance ??= new self();
        self::$instance->marks[$name] = [
            'start' => microtime(true),
            'memory' => memory_get_usage(),
            'peak'   => memory_get_peak_usage(),
        ];
    }

    public static function end(string $name): array {
        if (self::$instance === null || !isset(self::$instance->marks[$name])) {
            throw new \RuntimeException("Mark '$name' was not started");
        }
        $mark = self::$instance->marks[$name];
        $elapsed = microtime(true) - $mark['start'];
        $memoryDelta = memory_get_usage() - $mark['memory'];
        $peakDelta = memory_get_peak_usage() - $mark['peak'];

        return [
            'time_ms'    => round($elapsed * 1000, 2),
            'memory_bytes' => $memoryDelta,
            'peak_bytes'   => $peakDelta,
        ];
    }

    public static function report(): string {
        if (self::$instance === null) return "No profiling data\n";
        $lines = ["\n" . str_repeat("=", 50), "  Profiler Report", str_repeat("=", 50)];
        $lines[] = sprintf(
            "  %-25s %12s %12s",
            "Section", "Time (ms)", "Memory (B)"
        );
        $lines[] = str_repeat("-", 50);

        foreach (self::$instance->marks as $name => $mark) {
            $result = self::end($name);
            $memStr = $result['memory_bytes'] >= 0
                ? '+' . number_format($result['memory_bytes'])
                : number_format($result['memory_bytes']);
            $lines[] = sprintf(
                "  %-25s %12.2f %12s",
                $name,
                $result['time_ms'],
                $memStr
            );
        }

        $lines[] = str_repeat("=", 50);
        return implode("\n", $lines) . "\n";
    }
}

// Usage: wrap code sections with start/end
Profiler::start('bootstrap');
require_once __DIR__ . '/vendor/autoload.php';

// request_slowlog_timeout = 5s
// slowlog = /var/log/php-fpm/slow.log
// This logs the full backtrace of any request exceeding 5 seconds

// Benchmarking helper — compare two implementations
function benchmark(string $name, callable $fn, int $iterations = 1000): array {
    // Warm up
    for ($i = 0; $i < 10; $i++) $fn();

    // Measure
    $start = microtime(true);
    $memStart = memory_get_usage();
    for ($i = 0; $i < $iterations; $i++) $fn();
    $time = microtime(true) - $start;
    $memory = memory_get_peak_usage() - $memStart;

    return [
        'name'   => $name,
        'time'   => round($time * 1000, 2),
        'avg_ms' => round(($time / $iterations) * 1000, 4),
        'memory' => $memory,
        'ops_sec' => round($iterations / $time),
    ];
}

// Compare array_map vs foreach
$data = range(1, 10000);

$result1 = benchmark('array_map', fn() => array_map(fn($x) => $x * 2, $data), 1000);
$result2 = benchmark('foreach', function() use ($data) {
    $result = [];
    foreach ($data as $x) {
        $result[] = $x * 2;
    }
    return $result;
}, 1000);

echo "array_map: {$result1['avg_ms']}ms avg ({$result1['ops_sec']} ops/sec)\n";
echo "foreach:   {$result2['avg_ms']}ms avg ({$result2['ops_sec']} ops/sec)\n";
$winner = $result1['avg_ms'] < $result2['avg_ms'] ? 'array_map' : 'foreach';
$faster = abs($result1['avg_ms'] - $result2['avg_ms']) / min($result1['avg_ms'], $result2['avg_ms']) * 100;
